## 1. 背景与目标

### 1.1 为什么做

用户在选股 / 建仓 / 持仓跟踪过程中，存在以下真实痛点：

| 痛点 | 描述 | 严重度 |
|---|---|---|
| **B（最痛）** | 信息看完了仍然下不了手，缺乏"打分卡"式的量化判断；卖出/获利了结的节奏也同样模糊 | 🔥🔥🔥 |
| **A** | 看到一只股票后，不确定是否值得纳入观察池进一步分析（**门槛 Yes/No**，非排序筛选） | 🔥🔥 |
| **C** | 买完就忘了当初为什么买，缺少长期跟踪锚点 | 🔥 |
| **D** | 资深投资者的判断逻辑分散，难以系统整理与复用 | 🔥（单独立项） |

### 1.2 真实目标（重要）

不是做"又一个分析工具"，而是构建一个 **让用户从"凭感觉炒股"进化到"有自己交易策略"的成长系统**。

工具的副产品（用户每次看股票时反复关心的字段）会自然沉淀为用户自己的判断框架，再反向迭代工具本身。

### 1.3 设计原则

1. **信息层先行，框架层后置** —— 框架必须从真实使用中"长"出来，不在前期硬造
2. **AI 判断必须可解释** —— 结论 + 关键指标 + 推理链 + 反向信号四件套
3. **数据来源分级、个人使用** —— 第一阶段以无 cookie 公开数据源（akshare/efinance）为主；第二阶段引入 cookie 抓取以补全消息面/财务深度数据。所有抓取仅本地存储，非商业化
4. **Skill 单一职责** —— 每个 Skill 只做一件事，由 AgentTeam 编排
5. **可归档、可复盘** —— 每次分析生成独立 HTML，按股票/日期组织
6. **不重复造轮子** —— 优先 Cherry-pick 成熟开源代码（ZhuLinsen），存储委托给 GBrain
7. **结构化记忆优先于静态归档** —— Markdown Page → GBrain 自动入图谱，HTML 仅作为渲染产物

## 3. 形态与架构

### 3.1 形态

```
用户 ──▶ Hermes ──▶ AgentTeam ──▶ 多个 Skill 并行/串行调用
                                        │
                          ┌─────────────┼─────────────┐
                          ▼             ▼             ▼
                      生成 HTML    写入 GBrain    本地 JSON 备份
                      （给人看）   （给 AI 看）    （复盘原始）
```

- **不做独立 App / 后端服务**
- **以 Skill 为最小单元**，沉淀进 Hermes
- AgentTeam 负责编排（哪些并行抓数据、哪个汇总、哪个渲染、哪个入脑）
- **GBrain 通过 MCP 协议暴露 30+ 工具**，Hermes 直接调用

### 3.2 三层产物（双轨设计）

| 产物 | 给谁看 | 存哪 | 作用 |
|---|---|---|---|
| **HTML 报告** | 人 | `~/stock-reports/<code>_<name>/<date>.html` | 视觉化、可归档、可手动翻阅 |
| **Markdown Page** | AI / GBrain | `GBrain pages/stock-analysis/...` | 入脑、向量化、自动建图谱 |
| **原始数据 JSON** | 复盘工具 | `~/stock-reports/<code>_<name>/<date>_data.json` | 数据层备份，避免重抓 |

> **关键设计**：分析 Skill 的输出**统一是 Markdown Page**（带 frontmatter + 实体引用），HTML 由 Markdown 渲染派生。
> 这样改字段只需改一处，且 Markdown Page 天然适配 GBrain 的实体提取与 typed link 自布线。

### 3.3 GBrain 集成方式

GBrain 是 [garrytan/gbrain](https://github.com/garrytan/gbrain)（MIT，YC 出品的 Postgres-native Agent 记忆系统），核心能力：

- **三层叠加检索**：向量检索（pgvector） + 自布线知识图谱 + 混合搜索
- **零 LLM 实体提取**：每次写入自动建立 typed links（确定性、低成本）
- **MCP 暴露 30+ 工具**：包括 `query` / `ingest` / `brain-ops` / `briefing` 等
- **基准成绩**：完整图谱 P@5 49.1% / R@5 97.9%（比纯向量 RAG 高 31.4 个百分点）

**用法分工**：

| 场景 | 调用 |
|---|---|
| 写入分析报告 | `gbrain ingest` 或 `idea-ingest` |
| 召回历史分析 | `gbrain query "300750 历史分析"` |
| 跨次对比 | 由 `analyze` Skill 在分析前调用 query 拿历史摘要 |
| 板块/同业横向查询 | 借助 typed links：`belongs_to_sector` |

#### 3.3.1 降级策略（GBrain 不阻塞主流程）

GBrain 仅承担记忆增强，不在分析关键路径上：

| 异常 | 降级行为 |
|---|---|
| `ingest` 失败 | Markdown + HTML 仍正常落盘；失败的 page path 写入 `~/.stock-skills/ingest_retry.jsonl` 待补 |
| `query` 失败 | 跨次对比降级为"无历史 context"，分析照常进行，结果中标注 ⚠️ |
| GBrain MCP 整体不可达 | Skill 进入"stateless 模式"，仅产出本次 HTML / Markdown，不查询不写入 |

用户后续可通过 `gbrain ingest <path>` 手动补录失败队列。

### 3.4 预设的实体类型 + 关系类型

实体类型（GBrain Entity）：
- `Stock` — 个股（如 300750）
- `Sector` — 申万一级板块（如 新能源）
- `Industry` — 行业 / 概念板块（如 动力电池）
- `Strategy` — 策略（如 缠论一买、情绪周期顶部），含字段：
    - `source: baseline | user_custom`（baseline 来自 ZhuLinsen，user_custom 由用户在使用中沉淀）
    - `priority: reference | primary`（baseline 默认 reference，user_custom 默认 primary）
- `Report` — 一次分析报告
- `News` — 新闻 / 公告

关系类型（typed links）：
- `belongs_to_sector` (Stock → Sector)
- `belongs_to_industry` (Stock → Industry)
- `analyzed_on` (Stock → Report)
- `applies_strategy` (Report → Strategy)
- `mentioned_in` (Stock → News)
- `competes_with` (Stock → Stock)

> 后续扩展：`recommended_by` (Stock → 大V) / `held_in_portfolio` / `verified_against`（事后校验）

## 4. 个股情报页结构（10 个板块）

> 全部板块均默认启用，按下文优先级分阶段实现。

### 顶部
- **页头**：股票代码 / 名称 / 所属行业 / 分析时间
- **🎯 一句话摘要**（AI 生成，统领全文）

### 板块 1：板块与行业环境 ⭐
> 回答："这只股票所处的位置怎么样"

- **1.1 板块轮动（短中期资金视角）**
  - 申万一级板块为主，概念板块作为补充
  - 板块强度：近 5 / 20 日涨幅在全市场排名
  - 资金流向：板块净流入金额、连续天数
  - **轮动阶段判断**（启动初期 / 加速期 / 高位震荡 / 退潮中）
    - AI 给结论 + **置信度**
    - 关键指标快照
    - **推理链**（让用户能学习判断逻辑）
    - **反向信号**（提示 AI 可能误判的方向）
  - 板块龙头表现 vs 本股
  - [图表] 板块 vs 大盘 vs 本股 近 60 日相对强弱

- **1.2 行业景气度（中长期基本面视角）**

  > **分阶段实现说明**：
  > - **MVP 阶段（akshare/efinance 可覆盖）**：仅输出"通用版指标"——行业 ROE / 毛利率 / 增速中位数 / 同行业排位
  > - **第二阶段起（需 cookie 数据源）**：PMI、一致预期、政策导向、上下游传导、行业定制模板

  - 通用版指标：行业 ROE / 毛利率 / 增速中位数
  - 重点行业定制模板（**第二阶段起**，按用户常关注行业逐步补充）：
    - 制造业：PMI、原材料价格、库存周期
    - 消费：社零、客单价、行业增速
    - 科技：研发投入、订单/出货量
    - 金融：净息差、不良率
  - 一致预期：未来 1-2 年行业增速预测（**第二阶段起**）
  - 政策导向（利好/利空标注）（**第二阶段起**）
  - 上下游景气传导（**第二阶段起**）

- **1.3 个股 vs 板块 vs 行业（关键交叉点）**
  - 本股在板块内排位（涨幅 / 资金流入 / 估值）
  - 角色判断：板块龙头 / 板块跟随 / 板块拖后腿
  - **矛盾信号识别**（最有价值）：
    - 板块退潮但本股逆势 → 真强 or 假突破？
    - 板块大涨但本股没动 → 滞涨补涨 or 基本面有问题？

- 现价、涨跌幅、市值、PE、PB、ROE、股息率
- 同行业排位（PE 在行业第 X 位 / X 家）
- 52 周最高/最低、距高点距离

- 大单 / 特大单占比
- 北向资金持仓变化
- 融资融券余额变化
- [图表] 近 30 日资金流向

- 主力成本区估算
- 筹码集中度
- 当前价相对筹码峰位置
- [图表] 筹码分布图

### 板块 5：技术走势
- 多周期均线（日 / 周 / 月）

- 关键支撑 / 压力位
- [图表] 日 K + 主图指标

## 5. AI 判断输出规范（贯穿全文）

所有需要 AI 给"判断"的地方，统一遵循以下格式：

```
🎯 结论：xxx（置信度 高/中/低）

📊 核心指标快照
  ▸ 指标 1：值（含义）
  ▸ 指标 2：值（含义）
  ...

🧠 判断逻辑
  1. 由 [指标 X] 推出 [子结论 A]
  2. 由 [指标 Y + Z] 推出 [子结论 B]
  ⇒ 综合：[最终结论]

⚠️ 反向信号
  ▸ 可能反驳此结论的指标 / 视角
  → 让用户能保持怀疑
```

**意义**：
- 用户看到的不只是结论，是别人脑中的判断框架
- 看多了自然沉淀出"哪几个信号同时满足才下结论"的认知
- 这正是"沉淀自己的交易策略"的关键路径

## 6. 实施优先级与阶段划分

### 🥇 第一阶段（MVP）
**目标**：解决 A 痛点（准入判断 Yes/No）

- 板块 1：板块与行业环境
- 板块 2：基本盘
- 板块 3：资金面
- 一句话摘要

**产出**：用户输入股票代码，按分档输出：
- **首屏（板块 1：板块与行业环境）≤ 15 秒**
- **完整 MVP（板块 1+2+3+摘要）≤ 60 秒**
- **缓存命中（同日重复查询）≤ 3 秒**

让用户在 15 秒内即可决定"要不要继续往下看"，避免长等待。

### 🥈 第二阶段（深度补全）
**目标**：解决 B 痛点（建仓 / 卖出决策）

- 板块 6：业绩与财务
- 板块 7：消息面
- 板块 5：技术走势
- 板块 8：风险提示

**产出**：完整的"是否买入 / 何时止盈"决策依据。

### 🥉 第三阶段（精修）
**目标**：交叉验证 + 横向对比

- 板块 4：筹码分布
- 板块 9：同业对比
